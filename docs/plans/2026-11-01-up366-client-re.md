## 3. 任务

### P0-1 基线（只读）
1. `robocopy "C:\Program Files (x86)\up366\client" work\client /MIR /NFL /NDL`
2. 全量 `sha256+size+mtime` → `recon/inventory.csv`
**验收**：443 条目；原目录零写入（记录 mtime 前后对比）。

### P0-2 白捡源码
1. 解 3 个 `.map` 的 `sourcesContent` → `extract/xotFullScreen-src/`（Vue + XotPfs 播放器 + U3CompoLib 组件库）
2. 从 css.map 的 `D:/work/fullscreen-html/...` 反推构建机布局
**验收**：`src/components/XotPfs.vue` 等原文可读。

### P1 运行时通道（Gate）
后台启动，不抢焦点、不污染用户配置：
```
start "" /MIN up366.exe --remote-debugging-port=9222 --user-data-dir=%TEMP%\u3prof
```
1. 验证 `http://127.0.0.1:9222/json` 列出 targets → `mcp.rea.inspect_web_page`
2. 验证 `--inspect=9229`（`ws://127.0.0.1:9229`）→ `mcp.rea.observe_javascript_runtime`
3. 验证 `NODE_OPTIONS=--require hook.js`（hook 只写 alive 文件）
4. 验证 `ELECTRON_RUN_AS_NODE=1 up366.exe -e "…"`
**验收**：`recon/runtime-access.md` 记录 4 条通道可用性矩阵。任一可用即过 Gate；全否 → 走 P2 的静态分支。
**约束**：全程观察外联（先记 DNS/HTTPS 目标），必要时断网；测试后 `taskkill` 并删 `%TEMP%\u3prof`。

### P2 脱壳
1. 主进程 `--inspect` → 遍历 `require('module')._cache` 落盘 `filename+source`
2. 拿不到原文时 hook `fs.readFileSync` / `fs.promises.readFile` / `Module._compile`，按调用栈保存经过的 Buffer
3. 对 `app.u3a` 读取下断点（`mcp.rea.load_frida_script`），回溯解密函数 → 记录算法/密钥/IV 派生
4. 写 `tools/u3decrypt.py`，离线解 `app.u3a` + 43 个 `.u3enc`，与运行时 dump 交叉校验 sha256
5. 兜底：`mcp.rea.open_binary(up366.exe)` → `search_strings "u3a"` → `find_xrefs_to_name` → `analyze_function` → `decompile_all`，与上游 Electron 22.3.27 的 asar_util 做 diff
**验收**：`u3decrypt.py` 独立解出 `res/assets/index.html`（首行 `<!DOCTYPE html>`）与 `app.u3a` 内 `package.json`。

### P3 协议测绘（主目标）
1. `mcp.rea.analyze_web_bundle(cdp_endpoint, target_id, fetch_source_maps=true)` → chunk 图 + route + endpoint 候选
2. `mcp.rea.inspect_web_network_capture` 记录真实请求（含 gRPC/protobuf 解码）
3. 源码侧定位：`mcp.rea.trace_feature`（以接口路径为种子）+ `trace_javascript_semantics`，还原请求头组装与签名函数
4. 汇总 `recon/api.md`：baseURL、鉴权头、签名算法（参数排序/hmac/md5?）、时间戳与 nonce、错误码
5. 重放验证：脚本复现一次「登录 + 取题 + 提交」三段请求（不写库、不刷单）
**验收**：三段请求可独立复现；签名函数有源码位置（`file:line`）与输入输出样例。

### P4 前端控制 harness
1. `harness/attach.ps1`：后台起进程 + 取 targetId + 连 CDP + 注入 `harness/inject.js`
2. `inject.js` 提供：`u3.hook(obj,key)`、`u3.mock(url,handler)`（拦 fetch/XHR/WebSocket）、`u3.css(css)`、`u3.route()`
3. 持久化：CDP `Page.addScriptToEvaluateOnNewDocument` 保证刷新后仍生效；进程重启则由 attach 脚本重放
4. 记录「改了会不会被完整性校验打回」的实验结论
**验收**：不改安装目录的前提下，能在运行中的界面上替换一处文案并拦截一个接口返回。

### P5 安全评估
1. fuse 滥用：RunAsNode/NodeOptions/CliInspect → 任意本地代码以应用身份执行（`inspect_pe_load_config` 辅助确认加载链）
2. u3enc loader：自定义协议是否可路径穿越读任意文件；解密前是否校验路径
3. 更新链：`up366update.exe`（13MB）+ `runtime-check/up366RunTimeCheck.exe` — 下载源、是否 HTTPS、是否验签、是否可比对降级；`mcp.rea.inspect_pe_imports`/`inspect_pe_certificates`
4. 渲染侧：解包后读 `webPreferences`（nodeIntegration / contextIsolation / sandbox）、CSP、`shell.openExternal` 调用点
5. 依赖面：Electron 22.3.27 / Chromium 108 已知 CVE，标注可达性
**验收**：`recon/security.md` 每条含「证据位置 + 影响 + 复现条件 + 修复建议」。

### P6 ASES（可选）
解密 `plugins/ases/index.js` → `inspect_native_exports(libases.node)` → `inspect_native_api` 还原 wav→分数的输入输出约束。

### P7 收口
`git init`；每阶段一 commit；二进制/解包产物进 `.gitignore`，只提交脚本+文档+`recon/`。

## 4. 风险与边界

- **自校验**：F3 表明有 asar 完整性校验；只在副本操作，绝不动安装目录。
- **自更新**：`up366update.exe` 可能回滚改动；测试期先记录再禁用相关计划任务/服务。
- **联网上报**：启动即埋点。P1 起全程记录外联；必要时断网。
- **后台化**：一律 `/MIN` + 独立 `--user-data-dir`，结束即 `taskkill`，不占用前台窗口、不写用户真实配置。
- **用途边界**：本地只读分析与互操作/安全评估；不绕过付费、不重分发题库与模型。
- **性能**：exe 136 MB，静态全量反编译最贵，优先运行时。
