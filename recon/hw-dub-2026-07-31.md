> 目标：定位这条作业在客户端的完整链路，并确认 PC 端到底能做什么。

## 0. 结论

1. 这是课程 **9222783（2028届17班）** 下的一条 `type=1` 学习任务，`extParam.bookName = "配音达人"`，`xotParam.reportType = 13`。
2. **PC 客户端不做配音作答。** 点击该作业只会走 `showReport()`：
   `/client/report/type` 返回 `studytask_student_default` → 打开 `report.up366.cn` 的通用报告页。

   `"“合作配音练习”请前往学生APP作答。"`（`js_chunk-4a3539b4`）。

## 2. PC 端点击链路（代码 + 实测）

### 2.1 代码路径（`js_chunk-4a3539b4.9bf167d0.js`）

```

showReport(t):
  POST {report-api}/client/report/type  {type:"studytask",scope:"student",courseId,studyTaskId}
  → data = "studytask_student_default"
  → 若命中特殊名单（tsdcbg/yywxz 等）走 report1..report7 的专用页

```

## 5. 提交/评分链路（依据现有证据的边界）

能从 PC 侧证实的：

```
移动端录音 → 合成视频 → 上传 OSS(up366-voice-bucket1) → 写作品（dubId）
                                                   ↓
PC: 章节作品列表 /client/course/chapter/dub/info ← 读取
PC: 作业卡片 → /client/report/type → report1 报告页（未作答时为空）
```

**未能证实**的部分（不在 PC 客户端内，无法仅凭 PC 侧证据下结论）：
- 移动端提交的具体接口与字段；
- 分数计算方式（是否为 ASES 引擎，客户端 ases 插件面向的是朗读/听说，未见 dub 题型）；
- 作品的视频合成参数。

## 6. 复现方法

前置：`harness/dev-launch.ps1 -Offscreen -Keep` + `node harness/control-server.js 7801`，登录后。

```bash
export MSYS_NO_PATHCONV=1
# 1) 列课程
U3_FRAME="=local://res/index.html#/" node harness/u3.js eval "<fetch 封装 + /client/student/course/list>"
# 2) 列作业，搜 配音
U3_FRAME="=local://res/index.html#/" node harness/u3.js eval "<... /client/student/course/job courseId=9222783 ...>"
# 3) 章节作品
U3_FRAME="=local://res/index.html#/" node harness/u3.js eval "<... dsb-api /client/course/chapter/dub/info ...>"
```

> 请求封装要点：业务接口未带 ST 时先返回 `result.code = -24` + `data.serverTicket`，
> 需把 `?ticket=<serverTicket>` 拼回原 URL 重放一次（与客户端 `M2.post` 行为一致）。

## 7. 工具可用性说明（rea）

本轮按要求尝试用 rea 处理 JS 侧产物，结论：

| rea 能力 | 状态 |
|---|---|
| PE / ELF 分析（ghidra 前端的 `inspect_pe_*`） | 可用（前几轮已用） |
| `open_binary` 打开 JS | 可以打开（返回 `format: javascript`、sha256） |
| `binary_overview` / 反编译 | 不可用：provider 需要 Ghidra（未配置 `GHIDRA_INSTALL_DIR`）或 IDA/Hopper |
| `recover_javascript_sources` | 不可用：需要 `REA_WAKARU_COMMAND`（Wakaru ≥1.13，Linux x64），本机未安装 |

因此 JS 侧改用「客户端内注入 hook + 以真实登录态直接调接口 + iframe 跨源读取远端 H5」取证，
证据以 `接口响应 + 页面文本 + 静态偏移` 三项交叉。
